# Junior: Питання для співбесіди

Короткі орієнтири для відповідей. Формулюйте своїми словами та підкріплюйте прикладом із практики.

## ISTQB і базова теорія

1. **Чим відрізняються error, defect і failure?** Error — помилка людини; defect — її слід в артефакті; failure — видимий збій під час виконання.
2. **Чим тестування відрізняється від налагодження?** Тестування виявляє збої, налагодження знаходить причину в коді й виправляє.
3. **Назвіть принципи тестування.** Показує наявність дефектів; вичерпне тестування неможливе; раннє тестування; групування дефектів; парадокс пестициду; залежність від контексту; хибна думка про відсутність дефектів.
4. **Які рівні тестування існують?** Component, component integration, system, system integration, acceptance.
5. **Різниця між confirmation і regression testing?** Перше перевіряє виправлений дефект, друге те, що зміни не зламали решту.
6. **Що таке black-box і white-box?** Перше за вимогами/поведінкою, друге за структурою коду.
7. **Поясніть equivalence partitioning і boundary value analysis на прикладі.** Поле 18–60: класи `<18`, `18–60`, `>60`; межі 17, 18, 60, 61.
8. **Severity vs priority?** Серйозність — технічний вплив; пріоритет — терміновість для бізнесу. Наведіть приклад, де вони не збігаються.
9. **З чого складається хороший баг-репорт?** Заголовок, середовище, кроки, actual/expected, докази, severity.
10. **Smoke vs sanity vs regression?** Smoke перевіряє базову придатність збірки, sanity вузьку конкретну зміну, regression широку перевірку наявного.
11. **Що таке test case і чим він відрізняється від чек-листа?** Тест-кейс має передумови, кроки, дані й очікуваний результат; чек-лист це стислий перелік пунктів для перевірки.
12. **Що таке exploratory testing і коли воно корисне?** Одночасне навчання, дизайн і виконання; корисне, коли мало документації чи треба швидко знайти проблеми.

## Клієнт-сервер

13. **Що відбувається, коли ви вводите URL у браузері?** DNS-розв'язання, TCP/TLS-з'єднання, HTTP-запит, обробка на сервері, відповідь, відображення сторінки.
14. **Назвіть HTTP-методи та їхнє призначення.** GET, POST, PUT, PATCH, DELETE; згадайте безпечність і ідемпотентність.
15. **Що означають коди 200, 201, 400, 401, 403, 404, 500?** Успіх, створено, поганий запит, не автентифікований, заборонено, не знайдено, помилка сервера.
16. **Різниця між 401 і 403?** 401 немає чинної автентифікації; 403 автентифікація є, але прав немає.
17. **Як знайти запит до API в браузері?** DevTools → Network → Fetch/XHR.
18. **Що таке cookie і сесія?** Cookie зберігається в браузері й надсилається автоматично; сесія — стан користувача на сервері, що ідентифікується id у cookie.
19. **Як зрозуміти, де дефект: UI чи backend?** Порівняти відповідь API з тим, що показує UI: якщо API повертає неправильні дані, проблема на сервері, інакше у відображенні.

## API

20. **Що таке REST API?** Стиль API по HTTP, де ресурси мають URL, а дії виражені методами HTTP.
21. **Що перевірите в API-запиті?** Статус, тіло, заголовки, валідацію, авторизацію, збереження даних.
22. **Які негативні тести напишете для POST?** Порожнє тіло, відсутні обов'язкові поля, невірні типи, дублікати, відсутній токен.
23. **Для чого Postman environments?** Змінні для різних середовищ і токенів без правки запитів.
24. **Чим PUT відрізняється від PATCH?** PUT замінює ресурс цілком, PATCH змінює частину полів.
25. **Що таке JSON і які в ньому типи даних?** Текстовий формат обміну; string, number, boolean, null, object, array.

## Поведінкові

26. Розкажіть про найцікавіший дефект, який ви знайшли, і як ви його відтворювали.
27. Що ви зробите, якщо розробник не згоден, що це баг? (Покажіть вимогу чи очікувану поведінку, докази, залучіть BA/PO.)
28. Як ви визначаєте, що тестування можна завершувати? (Критерії виходу, ризики, покриття, стан дефектів.)
