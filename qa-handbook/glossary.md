# Глосарій

Англійські терміни подані так, як їх використовують у співбесідах і документації. Офіційні визначення дивіться в глосарії ISTQB.

| Термін | Українською | Коротко |
|---|---|---|
| Error / Mistake | Помилка людини | Дія людини, що призводить до дефекту |
| Defect / Bug | Дефект | Недолік у коді чи документі, що може спричинити збій |
| Failure | Збій | Видима невідповідність поведінки очікуваній |
| Root cause | Першопричина | Найглибша причина дефекту, усунувши яку, можна запобігти повторенню |
| Test basis | Тестова основа | Документи й знання, з яких виводять тести (вимоги, історії, код) |
| Test condition | Тестова умова | Що саме перевіряємо |
| Test case | Тест-кейс | Передумови, кроки, дані, очікуваний результат |
| Test suite | Набір тестів | Група тест-кейсів для спільного виконання |
| Test oracle | Тестовий оракул | Джерело очікуваного результату |
| Test data | Тестові дані | Дані, потрібні для виконання тесту |
| Test environment | Тестове середовище | Інфраструктура й конфігурація, де виконують тести |
| Test level | Рівень тестування | Component, integration, system, acceptance |
| Test type | Тип тестування | Функціональне, нефункціональне, структурне, пов'язане зі змінами |
| Black-box | Чорна скринька | Тести з вимог і поведінки, без знання коду |
| White-box | Біла скринька | Тести зі структури коду |
| Static testing | Статичне тестування | Огляди й статичний аналіз без виконання коду |
| Dynamic testing | Динамічне тестування | Тестування з виконанням програми |
| Regression testing | Регресійне тестування | Перевірка, що зміни не зламали наявне |
| Confirmation testing | Підтверджувальне тестування | Перевірка, що виправлений дефект справді усунено |
| Smoke testing | Димове тестування | Швидка перевірка, що збірка придатна для подальшого тестування |
| Sanity testing | Санітарне тестування | Вузька перевірка конкретної зміни чи виправлення |
| Exploratory testing | Дослідницьке тестування | Одночасне навчання, дизайн і виконання тестів |
| Coverage | Покриття | Частка покритих елементів (вимог, рішень, операторів) |
| Severity | Серйозність | Технічний вплив дефекту |
| Priority | Пріоритет | Терміновість виправлення з погляду бізнесу |
| Risk | Ризик | Ймовірність небажаної події × її вплив |
| Entry criteria | Критерії входу | Умови, за яких можна починати активність |
| Exit criteria | Критерії виходу | Умови, за яких активність вважають завершеною |
| Definition of Done (DoD) | Визначення готовності | Домовленості команди про «готово» |
| Traceability | Простежуваність | Зв'язок між вимогами, тестами й результатами |
| Flaky test | Нестабільний тест | Тест, що іноді проходить, іноді падає без змін коду |
| API | Програмний інтерфейс | Контракт взаємодії між програмними компонентами |
| Endpoint | Кінцева точка | URL + метод, за яким доступна операція API |
| Idempotency | Ідемпотентність | Повторний виклик дає той самий ефект, що й один |
| Payload | Тіло запиту/відповіді | Дані, що передаються в body |
| Latency | Затримка | Час відповіді |
| Throughput | Пропускна здатність | Кількість запитів за одиницю часу |
| SLA / SLO / SLI | Угода / ціль / показник рівня сервісу | Домовленість, мета й метрика доступності чи швидкості |
| Contract testing | Тестування контрактів | Перевірка, що клієнт і сервер дотримуються узгодженого формату обміну |
| Mock / Stub | Мок / заглушка | Імітація залежності для ізоляції тесту |
| CI/CD | Безперервна інтеграція/доставка | Автоматична збірка, тести й розгортання |
| Shift-left | Зсув уліво | Тестувати раніше в життєвому циклі |
| Observability | Спостережуваність | Здатність з логів, метрик і трасувань зрозуміти стан системи |
